# AgentWatch 0.2.0 — недельное испытание

## Что изменилось

Служба сохраняет прежние native collectors, интервалы опроса, минутные агрегаты, SQLite schema 1 и пакетную запись. Новая логика работает при запросе отчёта. Существующая история 0.1.0 читается без миграции.

- `weekly` создаёт Markdown или JSON: FACTS, отдельные INTERPRETATION с confidence/evidence/alternatives, качество данных, выбранные эпизоды, сессии, отметки и события.
- `mark "ноут начал тормозить"` сохраняет явную пользовательскую отметку; отчёт извлекает все доступные бакеты ±15 минут вокруг неё, а не только выбранные аномалии.
- `usage-sync` читает usage metadata Codex/Claude по запросу, в отдельном процессе CLI, и сохраняет только разрешённые поля в пользовательский SQLite.
- `sessions` и `events` дают структурированные представления для дальнейших клиентов. MCP, dashboard, GUI и автоматической оптимизации нет.
- Каждый запуск сборщика получает уникальный каталог с manifest и последовательными сегментами журнала. Предыдущие журналы не заменяются и автоматически не удаляются.

## Сборка и текущая служба

`scripts/Build.ps1` создаёт уникальный каталог с EXE, manifest, build logs и тестовыми артефактами. Указатель `artifacts/latest-build.json` позволяет найти последнюю успешную сборку; прежние каталоги остаются на месте. EXE в `artifacts/publish` от первой версии не перезаписывается.

```powershell
$root = 'C:\sarychev\Codex\AgentWatch'
$build = Get-Content -LiteralPath (Join-Path $root 'artifacts\latest-build.json') -Raw | ConvertFrom-Json
$aw = $build.File
& $aw version
# Новым CLI можно читать историю работающей старой службы:
& $aw weekly --since 7d
```

Во время подготовки служба 0.1.0 продолжает работать. Смена версии — отдельное явное действие пользователя. Сначала можно прочитать план, не останавливая службу:

```powershell
& 'C:\sarychev\Codex\AgentWatch\scripts\Update-Service.ps1' -Plan
```

Когда готовы перезапустить — в PowerShell **от имени администратора**:

```powershell
& 'C:\sarychev\Codex\AgentWatch\scripts\Update-Service.ps1'
```

Скрипт проверяет ownership markers, ImagePath и hash новой сборки; сохраняет старый EXE, останавливает только AgentWatch, архивирует согласованный комплект DB/WAL/SHM/config и журналы в защищённый `ProgramData\AgentWatch\archives\upgrade-*`, затем заменяет EXE и запускает службу. При ошибке запуска пытается вернуть прежний EXE. История БД не откатывается и не удаляется. Сам сценарий обновления/rollback требует повышенной проверки; подготовка его не выполняет.

## Отмечать заметные торможения

Отметки выполняются **обычным пользователем**, без повышения прав. Пока служба старая, используйте `$aw` из новой сборки; после обновления можно использовать установленный EXE.

```powershell
& $aw mark 'ноут начал тормозить'
& $aw mark 'задержка после запуска сборки' --at '2026-09-07T16:20:00+03:00'
```

Обе формы `mark "текст"` и `mark --note "текст"` поддерживаются. Текст — одна строка до 500 символов, без управляющих символов. Никакие действия и окна автоматически не записываются. Файлы находятся в `%LocalAppData%\AgentWatch\marks`; `--marks-dir` позволяет явно выбрать другое локальное хранилище.

## Сессии и usage перед отчётом

```powershell
& $aw usage-sync --since 7d --json
& $aw sessions --since 7d --json
& $aw weekly --since 7d --output (Join-Path $root ('artifacts\week-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.md'))
& $aw events --since 24h --json
```

Это ручной импорт по запросу; фонового watcher, scheduled task, hook или дополнительного сервиса нет. Перед итоговым недельным отчётом повторите `usage-sync`. Claude хранит локальные transcripts ограниченное время; не откладывайте импорт на месяцы. Если `budgetReached=true`, повторите импорт: завершённые строки продолжаются с сохранённого byte offset. Неполная последняя строка ждёт завершения записи агентом. По умолчанию импорт ограничен 64 МиБ, 100 изменённых файлов и примерно минутой обработки; максимум явного `--max-mib` — 256 МиБ.

Поиск по умолчанию: `.codex\sessions` и `.claude\projects` в профиле, указанном при установке. Он ограничен глубиной и числом файлов; reparse paths пропускаются. Для нестандартных мест задайте `--codex-root` (каталог sessions), `--claude-root` (каталог projects), либо конкретный файл:

```powershell
& $aw usage-sync --agent codex --file 'C:\path\session.jsonl' --json
```

Usage хранится отдельно в `%LocalAppData%\AgentWatch\usage\usage.db`; `--usage-dir` поддерживается импортом, sessions, weekly и events. Наличие других профилей, удалённых/cloud сессий, отсутствующих файлов и лимитов импорта означает неполноту, а не нулевое использование агента.

## Как читать результат

- **FACTS:** значения, интервалы, поля источника и контекст. Временной контекст сессии содержит общие метрики системы и всех процессов соответствующего вида агента; это не per-session CPU/I/O.
- **INTERPRETATION:** формулировка вывода, confidence `low`/`medium`/`high`, список evidence, альтернативные объяснения, следующий шаг. Confidence относится к конкретной формулировке, не доказывает причинность.
- Requested period, stored bucket span и observed seconds — разные величины. Сон, downtime и пробелы не объявляются потерянными данными или uptime компьютера. Крайние бакеты могут выходить за запрос.
- Valid seconds каждого показателя определяют доступность метрики. Свежесть и последнее состояние сборщиков описывают последнюю сохранённую партию, а не все семь дней.
- Session start появляется только при явном событии. `firstObservedUtc` — другой факт. Last activity не закрывает сессию. Неизвестные model/effort/end/tokens/cost остаются null.
- Матрица токенов различается: Codex input включает cache, Claude input исключает cache. Reasoning является частью output; эти числа нельзя повторно складывать.
- Claude assistant output может быть промежуточным. Его reported значение отделено от подтверждённого final output; полный cost по такому набору не вычисляется.
- Стоимость доступна только при полном наборе окончательных токенов и явном точном тарифе. Это API-equivalent estimate, не сумма к оплате по подписке. Настройка описана в SESSION_USAGE.md.

По умолчанию weekly смотрит семь дней; максимум — 31 день. Выбрано до 12 эпизодов, до 200 отметок/запусков, до 500 сессий, до 50 000 usage/activity записей и до 20 000 событий. Полный ресурсный контекст рассчитывается для первых 100 сессий и всех включённых отметок. Лимиты отражены в JSON и тексте; для подробностей сузьте период.

## Что проверить за неделю

Первые часы проверить `status`: обновляется ли last persisted sample, доступны ли нужные сборщики. В обычной работе оставить несколько отметок заметных задержек. Через сутки посмотреть `self` и размеры DB/WAL. Через неделю импортировать usage, сохранить weekly Markdown + JSON, затем сопоставить эпизоды с отметками. Не менять Windows или нагрузку специально ради красивого результата.

Сборка, тесты и измерения разработки сами создают нагрузку: старую историю сохраняем, но началом отдельного испытания следует считать выбранный новый запуск, а не всю предыдущую разработку. `runs --json` показывает его UTC start. Для точного календарного окна доступны `--from`/`--to` с явным часовым поясом.
